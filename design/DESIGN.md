# Hydro-Lines: Interface Design (v0.2, polish pass, aligned to code v0.1.0)

Files in `design/`:
- `mockup.html` is static and opens straight from disk.
- `mockup-data.js` is generated by `build_mockup_data.mjs` from the real `data/*.json` and `js/engine.js`.
- `mockup.png` is the 1600×900 render.
- `build_mockup_data.mjs` rebuilds the data file. Run it with `node design/build_mockup_data.mjs`. It reads `data/` and `js/` and writes only inside `design/`.

The mockup shows **real engine output** for the scenario `2025-06-24` (2025 peak demand day, dispatch ESTIMATE) at **hour 19**:
- model load 24,186 MW
- overloads TRA-RIC 108% and BUC-LON 128% (both on generic ESTIMATE limits)
- dispatchable headroom 553 MW
- score 70/100
- FETT 2,204 / 5,900 MW, which is the "FETT flow low" known issue

The map is an SVG stand-in for Cesium. It uses simplified OSM geometry and lake outlines drawn by hand.

## 1. Design stance

- **A control room, not a dashboard.** The look follows ISA-101 "high-performance HMI": a muted grey-blue base, with saturated red, amber and yellow reserved for abnormal states.
- **Two line-colour modes, never mixed.**
  - *Voltage mode* (default) colours lines by kV, slightly muted. Abnormal loading appears as a halo plus a % chip on top.
  - *Flow mode* (`F`, the existing `flows` layer) recolours lines by loading. Voltage then shows only through line width.
  - This fixes the v0.1 clash, where red 500 kV and red overload looked the same.
- **The globe stays the hero.** Panels dock to the edges, and the centre of the map is never covered except by a single callout for the selected object. `\` collapses everything except the top bar and status bar.
- **Only show what the engine computes.** The HUD shows only values that `E.solve()` or `data/*.json` provide today. Anything simulated, estimated or inferred carries a badge: `EST` (any `*_est`, `pos_est`, `est_membership` or `dispatch:'auto'` day), `SIM` (computed by the engine), or `PLAN` (from `planned.geojson`).

## 4. Alarms: rules on `R = E.solve()` (no separate alarm engine)

| Pri | Rule | Message |
|---|---|---|
| P1 | `R.loading[id] > 1` | Overload N% of L MW limit · flow MW |
| P1 | interface `loading > 1` | Interface N% of TTC |
| P1 | `R.shed > 0` or `R.island.length` | Islanded load N MW (bus list) |
| P2 | `0.9 ≤ loading ≤ 1` (branch or interface) | High loading N% |
| P2 | `abs(R.slackMW) > 1500` | REST slack large: rebalance |
| P2 | dispatchable headroom < 1000 MW (Σ `cap−mw` over GAS/HYDRO/OTHER) | Low headroom |
| P3 | `0.8 ≤ loading < 0.9` | Loading N% |
| EV | trip/restore, day/hour change, auto-balance | logged to Events, not counted as alarms |

- An alarm is keyed by `rule:objectId`. It is **raised** when the rule first becomes true and **clears** when it stops being true, then moves to Events.
- `A` acknowledges the selected alarm and `Shift+A` acknowledges all. Unacknowledged P1 alarms blink in the counter.
- An alarm whose limit is `limit_est` shows `EST limit`. On `dispatch:'auto'` days every alarm also shows "unvalidated", which addresses the open issue that peak-day overloads haven't been validated.
- Selecting an alarm row selects its object everywhere (tree, map and callout). `Enter` flies to it.

## 5. Grid Explorer (Regedit style) on `registry.json`

- **Root `HKONT`** has these children, taken from the registry's `path[0]`: `Generation` (208), `Transmission` (34), `Interties` (7), `Stations` (27 model buses), `Planned` (31), `History` (26). Two virtual roots come from GeoJSON: `OSM lines` (3,100, keyed `osm:way/…`) and `OSM substations` (428).
- **Tabs:**
  - *In view* uses the same tree filtered to entities whose lon/lat falls inside `viewer.camera.computeViewRectangle()`, recomputed 250 ms after the camera stops moving.
  - *Full directory* shows everything.
  - *Watch* lists starred ids stored in `localStorage['hl.watch']`, each with a live value.
- **Live value column:** tree rows show a value next to their name: branches show % loading (coloured by the flow ramp), stations show MW, and planned items show their ISD year.
- **Address bar** shows `HKONT\` + `path.join('\\')`.
  - Typing or pasting a path, or an id such as `br:BUC-LON`, resolves through a path→id map and calls `openId(id)`.
  - The deep link stays the existing `#open=<id>` (plus `view`, `day`, `hour`, `layers`, `year`), so there is no new URL scheme. `Ctrl+L` copies it.
- **Value pane** has columns Name | Type | Value | Src, and its rows are the same rows `table(rec)` already builds.
  - The existing type strings map to Regedit-style labels: string → `REG_SZ`; MW, kV, km and pu → `REG_DWORD`; date → `REG_DATE`; lonlat → `REG_GEO`; url and bus → `REG_LINK`; a live engine value → `REG_SIM`; tag → `REG_MULTI_SZ`.
  - Src shows source ids from `sources.json`, with the title on hover and the URL on click.
  - Any `*_est` field appends `EST`.
- **The faceplate goes away.** `#faceplate` content moves into the value pane. Branch actions (Trip/Restore) become a toolbar button above the value pane and the `T` key.

## 6. Keyboard map

`E` explorer · `R` right column · `B` dock · `\` collapse all · `1`–`4` kV layers · `S` `G` `F` `P` `H` layers · `L` inset cycle · `/` filter tree · `Ctrl+L` copy deep link · `Space` play/pause hours · `,` `.` hour −/+ · `Shift+,` `Shift+.` history year −/+ · `T` trip/restore selected branch · `A` / `Shift+A` ack · `Enter` fly to selected · `Esc` deselect · `?` key sheet.

Keys are ignored while an `<input>` or `<select>` has focus.

## 7. The ideas kept (4)

1. **The registry path is the address.** `HKONT\Transmission\230 kV\BUC-LON` works as the address bar, the search term and the citation anchor, and it is backed by `registry.json` `path[]` plus the existing `#open=` deep link.
2. **Time-machine strip.** The real `history.json` (1922–2026, 26 events) and planned ISDs (to about 2036) sit on one strip. Scrubbing shows the network as it was, ✝ markers for coal retirements, and amber dashed lines for planned work.
3. **Visible confidence.** EST, SIM and PLAN badges are computed from the real flags. There's a day-level "DISPATCH EST" chip, "EST limit" on alarms, and a `LOW?` marker on FETT until the known issue is fixed.
4. **Regional one-line inset.** A small SVG schematic of model buses for KW (then GTA, then Niagara) with live MW and %. It is cheap (no second Cesium viewer), readable at a glance, and gives the requested KW/GTA detail without cluttering the province view.

## 8. Implementation notes

- Panels are plain DOM over the Cesium canvas, so no build step. Keep `pointer-events` scoped so the globe stays draggable.
- Level of detail by camera height: above 400 km show 500/345 kV and stations of at least 500 MW; from 150 to 400 km add 230 kV and buses; below 150 km add 115 kV and all labels.
- Halos: a second, wider polyline under each hot branch (`PolylineGlowMaterialProperty`), built only for branches at 90% or more.
- Keep all colours in `:root` CSS variables, and mirror them into one JS `PALETTE` object read by `main.js`.
- Tests must keep `window.HL` and its existing members, because `tests/smoke.mjs` depends on them. Add `HL.alarms`, `HL.explorer` and `HL.keys` for new checks.

## 9. Changes in polish pass (v0.1 mockup → v0.2)

**Cut, because the engine doesn't model it or it's weak:**
- The frequency (Hz) gauge, since a DC flow has no frequency. Replaced by the **Balance** KPI and bar (REST slack MW).
- Operating reserve vs requirement. Replaced by **dispatchable headroom**, which is computable.
- The ice storm and weather layer, the `WX`/`CITY`/`TIE` rail buttons, and the Weather dock tab.
- The CO₂ readout, the "Objectives" panel and the 8,420 score. The real score is 0–100 from `score()`.
- The Québec intertie as its own live row. QC/MB/MN now share one read-only "Other" row from `other_net_export_h`.
- The 2003 blackout replay. It moves to the backlog and stays a timeline marker.
- The circular magnifier lens, replaced by the one-line inset.
- The fake `REG_*` values. The value pane now uses rows from `table(rec)`.
- The nav buttons, since Cesium's own camera controls are enough.

**Tightened or fixed:**
- Added the 345 kV layer (it exists in the data) and moved the hotkeys to `1`–`4`.
- Changed the 230 and 115 kV colours to avoid clashing with alarm and selection colours, and split Voltage mode from Flow mode.
- Added an **Interfaces panel** (FETT, QFW, FN, ON-MI, ON-NY), the most operator-relevant view the engine already produces.
- The top bar now uses the real controls (day, hour, Load×, Auto-balance, Reset) instead of a fake clock with 60× speed.
- Explorer roots, counts, the selected object and its values are real (`br:BUC-LON`). Tree rows carry live values. The Dispatch list moves to a dock tab.
- Alarm rules are defined against `solve()` fields, with EST and "unvalidated" tags.
- The timeline uses the real event types and planned ISDs.
- The mockup now renders from generated real data (`mockup-data.js`) rather than made-up numbers.

**Open issues the UI surfaces until they are fixed:**
- FETT runs low (`LOW?` marker).
- Peak-day overloads are unvalidated ("unvalidated" tag).
- The smoke test borrows Playwright (an implementation prompt covers this).
